# Step 10. 기능 나열

> 목적: 지금까지 논의에서 나온 **기능 아이디어를 하나도 빠뜨리지 않고** 모은다.

> **Guide:**
>
> 1. Agent가 `docs/proposal/04`~`docs/proposal/09`을 읽고, 언급된 **모든 기능**을 추출한다.
> 2. **순서·중요도·선후 관계 없이** 일렬로 나열한다.
> 3. 팀이 빠진 기능이 있으면 **팀이 추가한 기능**에 적는다.
>
> - 기능은 **사용자가 할 수 있는 일** 또는 **서비스가 제공하는 것** 단위로 쓴다. (예: 로그인, 일정 자동 추천, 알림 보내기)
> - 큰 덩어리(예: "앱 전체")로만 적혀 있어도 **일단 포함**하고, 안에 여러 기능이 섞여 있으면 **풀어서** 각각 적는다.
> - 비슷한 기능이라도 **논의에서 따로 나왔으면 각각** 적는다.
> - **이 단계에서 하지 않는 것:** 우선순위 정하기, 중요도 판단, MVP만 골라내기, 제외·합치기
> - 우선순위·제외는 **Step 14**에서 한다. 여기서는 **놓치지 않고 모으는 것**만 한다.

**프롬프트 예시**

```
docs/proposal/04~09을 읽고 docs/proposal/10_feature_list.md의 "Agent가 추출한 기능" 섹션만 채워줘.

규칙:
- docs/proposal/04~09 어디에든 나온 기능·아이디어를 빠짐없이 포함 (목적·가치, 여정, Pain/Wow, 가설, 키워드, 질문·답변 등)
- F-01부터 번호를 매겨 일렬로 나열 (번호·순서는 우선순위가 아님)
- 기능명은 짧고 구체적으로 (한 줄)
- 우선순위 판단·제외·MVP 선별 하지 않는다. 의심스러워도 일단 나열
- "팀이 추가한 기능" 섹션은 건드리지 않는다.
- 구조와 상단 Guide는 유지
```

## Agent가 추출한 기능

> `docs/proposal/04`~`docs/proposal/09`에서 나온 기능. **빠짐없이** 나열. Agent가 채운다.

- **F-01** 뉴스/아티클 링크 직접 입력
- **F-02** 링크(URL) 기반 입력 분석
- **F-05** AI 요약 섹션 — 뉴스 제목·언론사·일자·태그, AI 요약본, 원문 버튼, 핵심 키워드·관련 섹터 칩(전일대비 변동폭)
- **F-06** 전망 분석 결과 섹션 — '좋은 신호'/'주의할 신호' 카드 (관련 뉴스·리포트·애널리스트 의견)
- **F-07** 1·2·3차 후속 수혜 산업 그래프 (파급 경로를 노드 그래프로 시각화, 단계별 색 구분)
- **F-08** 섹터별 영향도 히트맵 (긍정/부정 색상·크기)
- **F-09** 노드 연결선 툴팁 — 한 줄 근거 + 근거 출처 뉴스 목록 표시
- **F-11** 크롬 익스텐션 (단축키로 보던 링크 전송)

## 팀이 추가한 기능

> Agent 목록에 없거나 빠진 기능. 팀이 직접 적는다.

- **F-03** 메인 화면 구성 — 상단 아티클 링크 입력창, 그 아래 인기 뉴스·주요 섹터 현황(섹터별 등락률)·최근 분석 내역 섹션
- **F-04** 로딩·분석 진행 상태 화면 ("분석 중...", "아티클 생성 중...")
- **F-10** 노드·히트맵 섹터 hover → 해당 섹터 Top5 종목 현황(전일대비 변동폭 %) 툴팁 표시 (영향력 확산 그래프 노드 / 섹터 영향도 히트맵 셀 공통)
- **F-12** 산업 지식그래프 섹션 — 뉴스의 중심 산업 기준, 전체 산업을 3D 네트워크로 연결해 회전/확대/축소하며 탐색
