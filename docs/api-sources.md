# 데이터 소스 · 외부 API 정리

수혜주.com이 **실제로 호출하는 외부 API**와, 검토했으나 **채택하지 않은 API + 이유**를 정리한다.
(시세/등락률 소스 조사 결과는 재조사 방지를 위해 근거까지 남긴다.)

---

## ✅ 사용 중인 API/소스

### 1. 네이버 금융 (비공식 모바일 API) — 인증 불필요

정상 브라우저처럼 `User-Agent` 헤더를 붙이고, 응답을 캐시한다. 비공식이라 차단 가능성이 리스크.

| 용도                   | 엔드포인트                                      | 쓰는 곳                                                                   |
| ---------------------- | ----------------------------------------------- | ------------------------------------------------------------------------- |
| 업종 등락률(WICS 79개) | `m.stock.naver.com/api/stocks/industry`         | 시장 섹터 API (#34), 주요 섹터 현황 GICS 그룹핑(#16), 뉴스 섹터 분류(#15) |
| 업종 구성종목          | `m.stock.naver.com/api/stocks/industry/{no}`    | 시장 히트맵 (#34), 종목명→섹터 역조회(#15)                                |
| 종목명→코드 자동완성   | `ac.stock.naver.com/ac`                         | 시세 join (#9) — 한글명으로 한·미 종목 매칭                               |
| 한국 종목 시세         | `m.stock.naver.com/api/stock/{code}/basic`      | 시세 join (#9)                                                            |
| 미국 종목 시세         | `api.stock.naver.com/stock/{reutersCode}/basic` | 시세 join (#9) — `NVDA.O`·`AFL` 등 접미사 가변                            |
| 인기 뉴스(많이 본)     | `api.stock.naver.com/news/ranknews`             | 인기 뉴스 API (#15/#53) — 실제 조회수 랭킹, API 키 불필요                 |

### 1-1. WICS→GICS 파생 로직 (원본 API 위에 얹은 가공, 신규 호출 없음)

원본 API(위 표)는 그대로 두고 같은 응답을 두 군데서 다르게 가공해 쓴다. 둘 다 신규 네트워크
호출 없이 `fetchIndustryResponse()`(WICS 79개 원본)를 재사용한다 — 코드: `lib/sources/naver.ts`.

- **주요 섹터 현황 그룹핑** (`fetchKrMajorSectors`, #34/#16): WICS 79개 업종을 국제표준 GICS
  11개 대분류(`WICS_TO_GICS_SECTOR`, `lib/gics-sectors.ts`)로 재그룹핑한다. 등락률은 단순 평균이
  아니라 **종목 수 가중평균** — 소수 종목의 이상치가 대형 업종의 대표값을 왜곡하지 않게 하기
  위함이다. WICS 원본을 그대로 상위 노출하면 반도체·2차전지 대신 문구류·담배 같은 생소한 업종이
  뜨는 문제가 있어 도입했다(#44).
  - **⚠️ 알려진 한계 (기존 설계 대비):** 이슈 #16의 원래 기획은 "주요 섹터(**반도체·2차전지 등**)"
    처럼 테마 단위 노출이었다. GICS 11개 대분류는 그보다 넓은 표준 분류라 반도체는 "정보기술"에
    묶여 개별로 드러나지 않고, 2차전지는 소재·산업재·정보기술에 걸친 밸류체인 테마라 GICS
    표준에 대응 카테고리 자체가 없다. 즉 "생소한 업종이 뜨는" 증상은 해결했지만, 기획이 원한
    테마 단위 노출 자체는 아직 구현되지 않았다. 개선하려면 테마 지수·테마 ETF 구성종목처럼
    테마 단위로 종목을 묶어주는 데이터소스에 대한 별도 기술조사(오픈 API 서치 등)가 선행돼야
    한다 — 아직 미착수.
- **뉴스 섹터 자동 분류** (`fetchStockNameToSectorInfo`, #15): WICS 79개 업종의 구성종목 전체를
  훑어 `종목명 → {GICS 대분류, WICS 소분류}` 매핑을 만든다. `GET /api/news`가 기사 본문의 종목명을
  1차로 조회하고, 종목명이 안 잡히면 `lib/gics-sectors.ts`의 키워드 매핑으로 폴백한다(순수 키워드
  매칭만 쓰면 "반도체 인력난" 같은 기사를 특정 종목으로 오탐하는 문제가 있어 종목명 매칭을
  우선한다). ranknews(#53)는 종목/섹터 정보를 안 주기 때문에 이 분류 파이프라인이 여전히
  필요하며, 매칭이 안 되면 `'증시'` 기본값으로 폴백한다.

### 2. GPT 게이트웨이 (엘리스, OpenAI 호환)

- `mlapi.run/{api_id}/v1` — 모델 `openai/gpt-5.4`
- 키: `OPENAI_API_KEY` (JWT, .env.local) / 주소: `GPT_BASE_URL`
- 용도: 뉴스 분석 (#9). **표준 OpenAI(gpt-4o 등)로도 전환 가능** — `GPT_BASE_URL` 비우면 자동.

### 3. 뉴스 본문 추출 (직접 스크래핑)

- `cheerio` 셀렉터맵(`#dic_area` 등) + `@extractus/article-extractor` 폴백
- 용도: URL → 본문 (#9)
- ⚠️ 저작권: 언론사 약관이 AI 학습 스크래핑 금지 → **본문 붙여넣기를 1차 입력**, 추출 본문은 영구 저장 안 함.

## ❌ 검토했으나 미채택 (재조사 방지)

### tradingeconomics

> https://github.com/tradingeconomics/tradingeconomics

- **유료** — 무료 `guest` 토큰이 폐지되어 인증 없이는 `401/410` 반환
- **한국 데이터가 얕음** — OTC/CFD 위주라 KRX 정식 종목·업종 커버가 부족
- **섹터(업종) API가 없음** — 수혜주의 핵심인 "산업별 영향도 히트맵" 용도에 부적합

→ 우리는 무료 + 한국 KRX 커버 + 업종 데이터가 필요한데 셋 다 안 맞아 탈락.

## 결론

- **한국 시세/업종** = 네이버 비공식 API (직접 검증됨, 무인증)
- **미국 시세** = 네이버 worldstock (`api.stock.naver.com`) — 별도 미국 API 불필요
- **뉴스** = 네이버 증권 ranknews(비공식, 무인증)
- **분석(LLM)** = 엘리스 게이트웨이 `gpt-5.4` (또는 표준 OpenAI)

상용 시세 API는 대부분 **유료 · 미국 편중 · 섹터 데이터 부재**로 탈락했고, 네이버 비공식 API가 무료로 한국+미국+업종+뉴스를 모두 커버해 채택했다.
